# @customs/db

Supabase migrations, generated database types, and the zod schemas shared by the API
(`apps/web/app/api`), the companion and the Discord bot.

```
supabase/config.toml        local stack config (project_id "customs-night")
supabase/migrations/        numbered SQL. Never edit one that has been applied; add a new file.
src/schemas/                zod schemas for every boundary. Imported by web, companion, discord.
src/types.ts                GENERATED by `pnpm db:types`. Do not hand-edit.
```

## Local stack

Tests and local development run against the Supabase CLI local stack, so nothing needs the hosted
project. Docker must be running.

```
pnpm db:start     # supabase start  -> prints the local API URL, anon key and service_role key
pnpm db:reset     # supabase db reset -> drops and replays every migration (and seed)
pnpm db:stop      # supabase stop
```

Put the printed local URL and keys in `apps/web/.env.local` (see `.env.example`). They are the same
on every machine and are not secrets, but they still do not belong in the repo.

## Migrations

```
supabase migration new <name>     # creates supabase/migrations/<timestamp>_<name>.sql
pnpm db:reset                     # apply everything locally, from scratch
pnpm db:migrate                   # supabase db push -> apply to the linked hosted project
pnpm db:types                     # regenerate src/types.ts from the LOCAL stack
```

`pnpm db:migrate` needs the project linked once per machine: `supabase link --project-ref <ref>`
from this directory.

Regenerate types after every migration and commit the result.

## Rules

- Every table gets Row Level Security. Public read on players (minus `discord_id`), ratings, games,
  `game_players`, splits, lobbies. Writes only through the service role the API uses.
- Players are keyed by PUUID. Lobbies dedupe on `lcu_party_id`, games on `lcu_game_id`.
